# Stack Decision: Ship-It Agent — Python + ADK

Date: 2026-07-18
Idea: Ship-It Agent
Status: Decided

## Decision

Use Python 3.11+ and Google's Agent Development Kit (ADK) instead of the default
Java/Spring Boot + LangChain4j stack.

## Context

The repo's default hackathon stack is Java-first: Spring Boot 3.x, Maven,
JUnit 5, LangChain4j on Vertex AI, and `google-cloud-*` Java client libraries.
This decision deviates from that default.

## Rationale

- ADK is Google's purpose-built agent framework and provides first-class
  primitives for multi-step agent workflows, built-in tool calling,
  session/memory management, and native integration with Vertex AI, BigQuery,
  and Document AI.
- ADK is currently Python-first; there is no mature Java equivalent that
  exposes the same agent orchestration model.
- The team wants to experiment with Google's latest agent SDK rather than
  wrapping LangChain4j around equivalent concepts.
- The demo can be delivered as a small Python FastAPI/Streamlit service plus
  the ADK agent, which is acceptable for a hackathon proof-of-concept.

## Trade-offs

- **Pros:** Native ADK integration with Vertex AI; cleaner multi-step agent
  code; access to ADK's built-in tracing and eval tooling.
- **Cons:** Team is primarily Java engineers; Python environment setup and
  dependency management will take extra time; ADK is still early and
  documentation/examples may be incomplete.

## Implications

- The `ideas/ship-it-agent.md` pitch reflects this Python + ADK stack.
- No other idea pitches are affected.
- If ADK proves too immature during the hackathon, the fallback is Python plus
  the standard `google-cloud-*` clients or, as a last resort, Java with
  LangChain4j.
